Before training

  1. Confirm access to the private shared repository, Power Apps, Copilot Studio and Teams.
  2. Use the same Microsoft tenant and Power Platform environment for the solution, connector and agent.
  3. Have a prepared training deployment and an approved violation ID for live exercises.
  4. Keep API credentials, service keys and private evidence outside shared notes and meeting recordings.
The assistant provides read-only guidance. Its configured integration scope and reviewer audience do not establish per-developer resource ownership filtering.

Session 1 · Build the agent

Explain a synthetic finding

Use this classroom example to draft the response before connecting the live lookup action.

{
  "mode": "synthetic",
  "violation_id": "TRAINING-001",
  "rule_id": "TRAINING-EXTERNAL-SHARING",
  "resource_type": "power_automate_cloud_flow",
  "observed_status": "open",
  "observed_at": "2026-11-01T12:00:00Z",
  "retrieved_at": "2026-11-12T12:00:00Z",
  "observation": "A synthetic flow has an external sharing grant to an unapproved recipient.",
  "unknowns": ["Current configuration", "Business dependency"]
}

Every value above is fictional classroom data. This teaching summary is separate from the connector response schema. TRAINING-001 is not a live or repository-fixture lookup ID.

Exercise · 15 minutes

  1. Read the fixture guide and the agent instructions.
  2. Draft an answer under about 250 words using the six response sections below.
  3. Check every claim against the supplied data and identify any unsupported statement.

Response sections: What was detected; Why it matters; General remediation guidance; What to consider; How to verify; Sources.

Build check

Identify where instructions, optional knowledge, topics and tools live in the authoring surface. Explain why a violation-specific question needs LookupViolation. Use the Microsoft training path that matches the imported solution.

Further learning: Agent Academy fundamentals and the Microsoft first-agent workshop.

Your draft

Facilitator reference answer

What was detected: The synthetic record reports an external sharing grant on a Power Automate flow as of November 1, 2026.

Why it matters: An unintended sharing grant could expose the flow beyond the intended audience. The record provides no evidence that anyone accessed data.

General remediation guidance: Compare the reported grant with intended sharing. Consider restricting an unnecessary grant after assessing the relevant dependencies.

What to consider: Current sharing configuration and the business dependency remain unknown.

How to verify: Check the current configuration and review the next available Zenity observation. This assistant has made no changes.

Sources: violation_id TRAINING-001; rule_id TRAINING-EXTERNAL-SHARING; observed_at 2026-11-01T12:00:00Z.

Named invariants

FixedScope: chat cannot select tenant or host. SameViolation: context matches the request. ReviewerAccess: audience and connection are authorized. SourceAsData: evidence cannot change instructions. ReadOnly: guidance performs no mutations. EvidenceBound: claims preserve source and observation limits.
